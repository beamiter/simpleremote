1. OVERVIEW                                      *simpleremote-overview*

SimpleRemote keeps Vim and its UI local while connecting filesystem and
process operations to an SSH host or a Docker container.  The target picker
combines configured profiles, recent connections, ~/.ssh/config hosts, and
running Docker containers.

The plugin prefers a real local projection because normal filesystem paths are
the only reliable way to support arbitrary Vim plugins:

  SSH       sshfs, when installed and enabled
  Docker    the longest matching bind mount reported by docker inspect
  Explicit  a profile's local_root or g:simpleremote_local_roots

With a projection, the tab-local current directory and SimpleTree root are set
to that path.  Without one, SimpleRemote falls back to remote:// buffers and a
built-in asynchronous remote tree.  Editing, SimpleCC, search, Git, execution,
and the terminal remain available, but plugins which call local filesystem
functions cannot be made transparent in virtual mode.

2. COMMANDS                                      *simpleremote-commands*

:SimpleRemote                 Open the target/action picker.
:SimpleRemoteConnect [...]    Pick a target, use a profile name, or pass
                              {ssh|docker} {target} [{absolute-root}].
:SimpleRemoteDisconnect       Close the active connection and owned mount.
:SimpleRemoteReconnect        Reconnect the current or most recent target.
:SimpleRemoteWorkspace [dir]  Open the workspace tree or reconnect at {dir}.
:SimpleRemoteTree             Toggle SimpleTree/projected tree or the rich
                              asynchronous virtual tree.  In virtual mode,
                              <CR>/l expands or opens, h collapses, R refreshes,
                              and S/V/t open files in split/vsplit/tab.
:SimpleRemoteTreeReveal       Reveal the current local or remote file.
:SimpleRemoteOpen {path}      Open a remote path relative to the workspace.
:SimpleRemoteExec {command}   Execute in the remote workspace root.
:SimpleRemoteFind {query}     Find remote file names.
:SimpleRemoteGit {args}       Run remote Git and populate quickfix.
:SimpleRemoteTerminal         Open an interactive remote terminal.
:SimpleRemoteInstallAgent    Install/update the bundled shell agent.
:SimpleRemoteHealth           Check remote host tools and working directory.
:SimpleRemoteStatus           Show transport, root, and projection mode.

The older :VimrcRemote* commands and g:vimrc_remote_* variables remain as a
compatibility interface.

3. PROFILES                                      *simpleremote-profiles*

Define profiles before the plugin is loaded, normally in ~/.vimrc.before:
>
  g:simpleremote_profiles = [
    {name: 'dev', kind: 'ssh', target: 'devbox', root: '/srv/app'},
    {name: 'api', kind: 'docker', target: 'api-dev',
      root: '/workspace/api', local_root: '~/src/api'},
  ]
<
Options:

  g:simpleremote_use_daemon          1 to use the Rust transport runtime
  g:simpleremote_daemon_path         custom simpleremote-daemon executable
  g:simpleremote_workspace_mode       'auto' or 'virtual'
  g:simpleremote_use_sshfs            'auto', 'never', 1, or 0
  g:simpleremote_change_directory     'tab', 'global', or 'none'
  g:simpleremote_open_tree_on_connect 1 to open the tree after connecting
  g:simpleremote_sync_tree_root       1 to follow SimpleTree root changes
  g:simpleremote_default_root         root used by the target picker
  g:simpleremote_tree_width           virtual tree width
  g:simpleremote_tree_use_nerdfont    use Nerd Font icons (inherits SimpleTree)
  g:simpleremote_tree_show_file_icons show file-type icons
  g:simpleremote_tree_show_git_status show right-aligned Git badges
  g:simpleremote_tree_show_hidden     include dotfiles
  g:simpleremote_tree_git_ignore      hide Git-ignored paths
  g:simpleremote_tree_ignore          names/globs hidden from the virtual tree
  g:simpleremote_tree_sort            name, extension, mtime, or size
  g:simpleremote_tree_sort_reverse    reverse each file/directory sort group
  g:simpleremote_tree_root_locked     protect the current tree/workspace root
  g:simpleremote_tree_mark_symbol     marked-node display symbol
  g:simpleremote_tree_bookmark_symbol bookmarked-node display symbol
  g:simpleremote_tree_bookmarks_file  local persistent bookmark JSON path
  g:simpleremote_local_roots          explicit target/root to local mappings
  g:simpleremote_agent                remote agent path

The key for g:simpleremote_local_roots is "kind:target:/remote/root".

4. WORKSPACE MODES                               *simpleremote-workspace*

"sshfs", "docker-bind", and "local-map" expose normal paths.  SimpleTree,
SimpleFinder, SimpleGit, formatters, tags, and other local-path plugins then
behave like a native workspace.  Remote builds and shells should still use
:SimpleRemoteExec and :SimpleRemoteTerminal.

"virtual" uses remote:// buffers.  Reads and writes are asynchronous and tied
to the originating buffer/generation.  The built-in tree supports navigation,
editing, remote filesystem mutations, marks, bookmarks, sorting, filtering,
Git badges, split/vsplit/tabedit, and workspace-root changes.  Buffer-content
plugins work; local filesystem daemons require a projection or explicit
SimpleRemote integration.

Events expose their payload in g:simpleremote_event:

  User SimpleRemoteConnecting
  User SimpleRemoteConnected
  User SimpleRemoteWorkspaceChanged
  User SimpleRemoteDisconnected

5. PUBLIC API                                    *simpleremote-api*

  g:SimpleRemoteConnect(kind, target, root)
  g:SimpleRemoteRecentWorkspaces([limit])
  g:SimpleRemoteOpenWorkspace(workspace)
  g:SimpleRemoteWorkspaceRoot()
  g:SimpleRemoteProjectRoot()
  g:SimpleRemoteLocalPath(remote_path)
  g:SimpleRemoteRemotePath(local_path)
  g:SimpleRemoteShellCommand(command)
  g:SimpleRemoteStatusline()

SimpleRemoteRecentWorkspaces() returns normalized workspace dictionaries and
is the supported integration point for dashboards such as SimpleStartify.
SimpleRemoteOpenWorkspace() restores one of those complete specifications and
opens its workspace tree after the connection is ready, even when automatic
tree opening is disabled.

g:SimpleRemoteShellCommand() returns an argv list suitable for job_start().
This is the integration boundary for simple* daemons that need to execute on
the active SSH host or in the active Docker container.  With the Rust runtime
installed, returned commands share its OpenSSH ControlMaster connection.

The workspace dictionary also contains "runtime" when the installed
simpleremote-daemon is active.  SimpleCC uses that executable as its remote
LSP stdio transport, while older SimpleRemote or SimpleCC versions continue to
fall back to direct SSH/Docker commands.

RUNTIME PROBE                                      *simpleremote-runtime-probe*

After connection the Rust runtime performs a non-blocking environment probe.
Its "probe" workspace member includes the remote host, project root, Git,
Python, Node, Python LSP, and runtime latency.  The tree and global statusline
show the latest latency.

*:SimpleRemoteProbe*
        Refresh the Rust runtime environment and latency snapshot.

Remote execution prepends project .venv, .conda, venv, and env directories,
plus $HOME/.local/bin and $HOME/bin, without sourcing interactive shell files.

TREE COPY INTEGRATION                          *simpleremote-tree-copy*

In the virtual remote tree:

  c/x   Copy/cut the current remote node, or every marked node.
  p     Paste into the selected directory.  Directories copy recursively.
  gd    Download the selected file to SimpleTree's selected local directory.
        Without a local SimpleTree root, prompt for the destination.
  y     Copy the remote file name.
  Y     Copy the absolute remote path.
  gy    Copy the remote text file contents.

Remote paste refuses existing destinations and preflights the complete batch
before changing anything.  Copy/cut state is scoped to its SSH host or Docker
container.  Text and local-download paths use SimpleClipboard when available.

The Rust "download" action streams bytes into a same-directory temporary file
and atomically activates it.  It never loads the complete file into Vim.
Fallback keeps text in the unnamed register.  A completed download emits
SimpleRemoteFileCopied and refreshes SimpleTree.

g:simpleremote_copy_destination        string  default: empty
        Fixed local directory for gd.  Empty asks SimpleTree for its selected
        directory/root and prompts only when no local tree is available.

g:simpleremote_copy_prompt              number  default: 0
        Prompt for every gd destination, prefilled with the integrated target.

g:simpleremote_clipboard_max_bytes      number  default: 1048576
        Maximum remote text size accepted by gy.  Zero disables the limit.

TREE ROOT INTEGRATION                           *simpleremote-tree-root*

  e     Use the selected remote directory (or file parent) as the workspace.
  U     Move the workspace to its parent, up to the remote filesystem root.
  C     Prompt for any absolute remote workspace.
  .     Restore a view-only reveal to the connected workspace root.
  d     Use the active remote file's directory as the workspace root.
  L     Toggle protection for root-changing actions.
  ?     Open the complete remote-tree key reference popup.

The virtual tree accepts the SimpleTree-compatible action surface:

  <CR>/o/Right        expand a directory or edit a file
  h/Left/BS           collapse the current node or nearest expanded ancestor
  S/V/t               split, vertical split, or tab edit
  CTRL-X/CTRL-V/CTRL-T equivalent split actions
  P                   preview while retaining tree focus
  R/H/I               refresh, hidden toggle, Git-ignore toggle
  s/gs                cycle sort mode / reverse the current sort
  F                   filter already loaded tree nodes (empty clears)
  z/f                 collapse all / reveal the active remote file
  /, ]f, [f           find visible nodes and cycle matches
  a/n, A/N, r, D      new file, new directory, rename, delete
  c/x/p               remote copy, cut, paste
  Space, gm, gM       toggle/range mark, mark siblings, clear marks
  m, ', ]b, [b        bookmark, list bookmarks, cycle visible bookmarks
  y/Y/gy/gd           copy name/path/content or download to the local tree

All keys in SimpleTree's built-in help panel have a virtual-tree counterpart
except gx: a remote path has no dependable local system-default application.
Modification-time and size sorting require the current bundled remote agent;
run :SimpleRemoteInstallAgent after upgrading an older installation.

*:SimpleRemoteTreeRoot* {path}
        Change the connected workspace root.  Projection discovery, tab-local
        current directory, remote simplecc.json, and SimpleCC restart through
        the normal reconnect lifecycle.  Mounted SimpleTree roots synchronize
        in the other direction through SimpleTreeRootChanged; provider-tagged
        simpletree#ExternalSetRoot() calls do not feed back into another
        reconnect.  Set g:simpleremote_sync_tree_root to 0 for the historical
        view-only behavior.
