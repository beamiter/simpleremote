1. OVERVIEW                                      *simpleremote-overview*

SimpleRemote keeps Vim and its UI local while connecting filesystem and
process operations to an SSH host or a Docker container.  The target picker
combines configured profiles, recent connections, ~/.ssh/config hosts, and
running Docker containers.

The plugin prefers a real local projection because normal filesystem paths are
the only reliable way to support arbitrary Vim plugins:

  SSH       sshfs, when installed and enabled
  Docker    the longest matching bind mount reported by docker inspect
  Explicit  a profile's local_root or g:simpleremote_local_roots

With a projection, the tab-local current directory and SimpleTree root are set
to that path.  Without one, SimpleRemote falls back to remote:// buffers and a
built-in asynchronous remote tree.  Editing, SimpleCC, search, Git, execution,
and the terminal remain available, but plugins which call local filesystem
functions cannot be made transparent in virtual mode.

2. COMMANDS                                      *simpleremote-commands*

:SimpleRemote                 Open the target/action picker.
:SimpleRemoteConnect [...]    Pick a target, use a profile name, or pass
                              {ssh|docker} {target} [{absolute-root}].
:SimpleRemoteDisconnect       Close the active connection and owned mount.
:SimpleRemoteReconnect        Reconnect the current or most recent target.
:SimpleRemoteWorkspace [dir]  Open the workspace tree or reconnect at {dir}.
:SimpleRemoteTree             Toggle SimpleTree/projected tree or the rich
                              asynchronous virtual tree.  In virtual mode,
                              <CR>/l expands or opens, h collapses, R refreshes,
                              and S/V/t open files in split/vsplit/tab.
:SimpleRemoteTreeReveal       Reveal the current local or remote file.
:SimpleRemoteOpen {path}      Open a remote path relative to the workspace.
:SimpleRemoteExec {command}   Execute in the remote workspace root.
:SimpleRemoteFind {query}     Find remote file names.
:SimpleRemoteGit {args}       Run remote Git and populate quickfix.
:SimpleRemoteTerminal [cmd]   Open an interactive remote terminal, or run
                              {cmd} in one.
:SimpleRemoteUpload {local} [dir]
                              Upload a local file or directory into the
                              remote workspace ({dir} defaults to the tree
                              root or the workspace root).
:SimpleRemoteDownload {remote} [local]
                              Download a remote file or directory; {local}
                              defaults to SimpleTree's selected directory or
                              the current directory.
:SimpleRemoteInstallAgent    Force-reinstall the bundled shell agent.  Not
                              normally needed: every connection installs or
                              updates the agent itself.
:SimpleRemoteHealth           Check remote host tools and working directory.
:SimpleRemoteReloadConfig     Re-read the remote simplecc.json and announce it
                              (see SimpleRemoteConfigChanged below).
:SimpleRemoteStatus           Show transport, root, and projection mode.

The older :VimrcRemote* commands and g:vimrc_remote_* variables remain as a
compatibility interface.

3. PROFILES                                      *simpleremote-profiles*

Define profiles before the plugin is loaded, normally in ~/.vimrc.before:
>
  g:simpleremote_profiles = [
    {name: 'dev', kind: 'ssh', target: 'devbox', root: '/srv/app'},
    {name: 'api', kind: 'docker', target: 'api-dev',
      root: '/workspace/api', local_root: '~/src/api'},
  ]
<
Options:

  g:simpleremote_use_daemon          1 to use the Rust transport runtime
  g:simpleremote_daemon_path         custom simpleremote-daemon executable
  g:simpleremote_workspace_mode       'auto' or 'virtual'
  g:simpleremote_use_sshfs            'auto', 'never', 1, or 0
  g:simpleremote_change_directory     'tab', 'global', or 'none'
  g:simpleremote_open_tree_on_connect 1 to open the tree after connecting
  g:simpleremote_sync_tree_root       1 to follow SimpleTree root changes
  g:simpleremote_default_root         root used by the target picker
  g:simpleremote_tree_width           virtual tree width
  g:simpleremote_tree_use_nerdfont    use Nerd Font icons (inherits SimpleTree)
  g:simpleremote_tree_show_file_icons show file-type icons
  g:simpleremote_tree_show_git_status show right-aligned Git badges
  g:simpleremote_tree_show_hidden     include dotfiles
  g:simpleremote_tree_git_ignore      hide Git-ignored paths
  g:simpleremote_tree_ignore          names/globs hidden from the virtual tree
  g:simpleremote_tree_sort            name, extension, mtime, or size
  g:simpleremote_tree_sort_reverse    reverse each file/directory sort group
  g:simpleremote_tree_root_locked     protect the current tree/workspace root
  g:simpleremote_confirm_delete       0 to delete tree nodes without asking
  g:simpleremote_tree_mark_symbol     marked-node display symbol
  g:simpleremote_tree_bookmark_symbol bookmarked-node display symbol
  g:simpleremote_tree_bookmarks_file  local persistent bookmark JSON path
  g:simpleremote_local_roots          explicit target/root to local mappings
  g:simpleremote_agent                remote agent path
                                      (default ~/.cache/vimrc/simpleremote-agent.sh)
  g:simpleremote_agent_source         local agent script shipped to targets
                                      (default bin/simpleremote-agent.sh)

The key for g:simpleremote_local_roots is "kind:target:/remote/root".

4. WORKSPACE MODES                               *simpleremote-workspace*

"sshfs", "docker-bind", and "local-map" expose normal paths.  SimpleTree,
SimpleFinder, SimpleGit, formatters, tags, and other local-path plugins then
behave like a native workspace.  Remote builds and shells should still use
:SimpleRemoteExec and :SimpleRemoteTerminal.

"virtual" uses remote:// buffers.  Reads and writes are asynchronous and tied
to the originating buffer/generation.  The built-in tree supports navigation,
editing, remote filesystem mutations, marks, bookmarks, sorting, filtering,
Git badges, split/vsplit/tabedit, and workspace-root changes.  Buffer-content
plugins work; local filesystem daemons require a projection or explicit
SimpleRemote integration.

Events expose their payload in g:simpleremote_event.  Every payload carries
"event" (the event name), "status" (g:simpleremote_status at the time) and
"time"; the fields listed are added on top:

  User SimpleRemoteConnecting        the connection spec {kind, target, root}
  User SimpleRemoteConnected         the workspace snapshot (see below)
  User SimpleRemoteWorkspaceChanged  the snapshot after a projection was
                                     activated (local_root, mode)
  User SimpleRemoteRuntimeReady      the snapshot once "probe" is populated;
                                     also fired after Connected when the
                                     probe finished during the handshake
  User SimpleRemoteTreeRootChanged   {root, workspace, mode} for a view-only
                                     tree re-root
  User SimpleRemoteBufferRead        {type: 'buffer-read', bufnr, path,
                                     workspace} after a remote:// buffer was
                                     (re)filled and its filetype detected
  User SimpleRemoteFilesChanged      {changes: [{path, type}], workspace}
                                     for paths made by the tree, uploads and
                                     API writes — not by buffer writes, which
                                     fire BufWritePre/BufWritePost like local
                                     files.  `type` is 'created', 'changed'
                                     or 'deleted' as the operation intends it:
                                     an upload always reports 'created' and
                                     SimpleRemoteWriteFile() always reports
                                     'changed', neither probes the remote
                                     first, so a listener that cares about the
                                     difference must check for itself
  User SimpleRemoteConfigChanged     {config} when the remote simplecc.json
                                     was reloaded on a live connection by
                                     :SimpleRemoteReloadConfig.  It is only
                                     emitted when something listens for it;
                                     with no listener, :SimpleCCRestart is run
                                     instead when that command exists
  User SimpleRemoteFileCopied        {remote, local} after a download
  User SimpleRemoteFileUploaded      {remote, local} after an upload
  User SimpleRemoteDisconnected      {reason}: 'disconnect' for a user or
                                     transport disconnect, 'reconnect' when
                                     the connection is being replaced (a
                                     workspace switch fires Disconnected,
                                     Connecting, Connected in that order).
                                     A transport that died on its own adds
                                     cause: 'transport-exit' and its exit
                                     `code`

g:simpleremote_workspace is unlet before Disconnected fires, so a listener
that needs to know which workspace went away must have remembered it.
WorkspaceChanged can arrive BEFORE Connected: a projection discovered during
the handshake (local-map, docker-bind, an already-mounted sshfs) is activated
inside it.  The Connected snapshot is always authoritative.

The workspace snapshot, also kept in g:simpleremote_workspace while a
connection is ready:

  id            connection generation, changes on every (re)connect
  kind, target  'ssh' or 'docker', and the host or container
  root          absolute remote workspace root
  tree_root     the tree's view root (equals root unless detached)
  local_root    local projection of root, or '' in virtual mode
  mode          'virtual', 'mounting', 'sshfs', 'docker-bind', 'local-map'
  runtime       path of the simpleremote-daemon in use, or ''
  runtime_version, protocol
                the runtime's version and the transport protocol:
                'json' (runtime bridge), 'exec' (older runtime) or
                'legacy' (no runtime)
  probe         {protocol, host, root, git, python, python_version, node,
                python_lsp, rg, tar, uname, runtime_ms, runtime_version,
                status} from the runtime probe, plus `error` when it wrote to
                stderr.  {} without a runtime, and {status: -1} while the
                probe is still in flight — test for a key you need (for
                example has_key(probe, 'runtime_ms')) rather than for
                emptiness
  uri           'remote://' .. root

5. PUBLIC API                                    *simpleremote-api*

  g:SimpleRemoteConnect(kind, target, root)
  g:SimpleRemoteRecentWorkspaces([limit])
  g:SimpleRemoteProfiles()
  g:SimpleRemoteOpenWorkspace(workspace)
  g:SimpleRemoteWorkspaceRoot()
  g:SimpleRemoteProjectRoot()
  g:SimpleRemoteIsVirtual()
  g:SimpleRemoteLocalPath(remote_path)
  g:SimpleRemoteRemotePath(local_path)
  g:SimpleRemoteShellCommand(command)
  g:SimpleRemoteExecArgv()
  g:SimpleRemoteExecute(command, Callback)
  g:SimpleRemoteReadFile(path, Callback)
  g:SimpleRemoteWriteFile(path, content, Callback)
  g:SimpleRemoteListDirectory(path, Callback)
  g:SimpleRemoteDownload(remote, local [, options [, Callback]])
  g:SimpleRemoteUpload(local, remote [, options [, Callback]])
  g:SimpleRemoteTerminalSpec([command])
  g:SimpleRemoteTreeSetRoot(path)
  g:SimpleRemoteStatusline()
  g:SimpleRemoteRuntimeCapabilities()
  g:SimpleRemoteSessionLines()

SimpleRemoteRecentWorkspaces() returns normalized workspace dictionaries and
is the supported integration point for dashboards such as SimpleStartify.
SimpleRemoteProfiles() returns the configured profiles in the same shape with
"source: 'profile'"; a profile may have an empty root, in which case opening
it prompts for one.  SimpleRemoteOpenWorkspace() restores one of those
specifications and opens its workspace tree after the connection is ready,
even when automatic tree opening is disabled.

SimpleRemoteExecArgv() returns an argv prefix — the runtime's `exec` action
with the workspace root — to which a caller appends a program and its
arguments.  Every element is quoted for the remote shell individually, so
this is the right choice for tools that build a real argv (SimpleGit's
daemon runs `git -C dir …` this way).  It is empty without an argv-safe
transport: plain ssh without the runtime re-joins arguments through the
login shell.  SimpleRemoteShellCommand() remains the choice for shell
scripts.

SimpleRemoteExecute() runs a shell command in the workspace root over the
persistent agent connection and calls Callback(ok, output) with the combined
output; SimpleRemoteWriteFile() writes a text file atomically and calls
Callback(ok, path-or-error); SimpleRemoteListDirectory() lists a directory
and calls Callback(ok, entries) with {name, path, type, size, mtime}
dictionaries (type is 'f', 'd' or 'l').  ReadFile, WriteFile and
ListDirectory refuse paths outside the workspace; Execute takes a shell
command, not a path, and runs whatever it is given.  All of them reply
synchronously with ok = false when no workspace is ready.

SimpleRemoteDownload() and SimpleRemoteUpload() stream a file or a directory
across the boundary.  Upload infers {recursive} from the local path; Download
needs {recursive: true} for a remote directory, because only the remote side
knows what the path is (the :SimpleRemoteDownload command probes it with
`test -d` first).  {force: true} replaces an existing destination; without it
either direction fails with 'already exists', through the runtime and through
the scp/docker-cp fallback alike.  A download never replaces a local
directory, forced or not.  Callback(ok, {remote, local, error}) runs when the
transfer finishes and the matching SimpleRemoteFileCopied /
SimpleRemoteFileUploaded event fires.

SimpleRemoteRuntimeCapabilities() returns the installed runtime's
capabilities object ({} without a runtime): version, bridge_protocol,
actions, agent_protocols, agent_bootstrap, recursive_transfer, tty.

SimpleRemoteSessionLines() returns the Vim script lines a session file needs
to bring the connected workspace back (see |simpleremote-suite| for
SimpleStartify).

g:SimpleRemoteShellCommand() returns an argv list suitable for job_start().
This is the integration boundary for simple* daemons that need to execute on
the active SSH host or in the active Docker container.  With the Rust runtime
installed, returned commands share its OpenSSH ControlMaster connection.

SimpleRemoteReadFile() asynchronously reads a text file inside the active
workspace without opening a buffer.  Callback is called as (ok,
content-or-error).  Relative paths use the workspace root; paths outside the
workspace are rejected.  SimpleFinder uses this API for virtual-workspace
previews.

SimpleRemoteTerminalSpec() returns the argv, label and workspace metadata for
an SSH/Docker terminal.  It returns an empty dictionary until a workspace is
ready.  SimpleTerminal uses this API to provide the same popup/session UI for
local and remote shells.

SimpleRemoteTreeSetRoot() changes the real workspace when
g:simpleremote_sync_tree_root is enabled. SimpleTree and SimpleFinder use it
for bidirectional root synchronization.

The workspace dictionary also contains "runtime" when the installed
simpleremote-daemon is active.  SimpleCC uses that executable as its remote
LSP stdio transport, while older SimpleRemote or SimpleCC versions continue to
fall back to direct SSH/Docker commands.

6. RUST RUNTIME                                  *simpleremote-runtime*

`install.sh` builds `lib/simpleremote-daemon`, a small Rust process that owns
the local end of every transport.  It keeps no state between invocations:
one process per connection, command, probe or transfer.

  agent      the persistent connection.  With `--protocol json` the runtime
             is a bridge: Vim exchanges one JSON object per line
             ({id, op, path|command|content_b64} in, {id, ok, data|data_b64}
             out) and the runtime performs every base64 step of the agent's
             line protocol in-process, so no `base64` process is spawned per
             request any more.  Payloads that are not valid UTF-8 travel as
             data_b64 so latin-1 or binary files round-trip byte for byte.
  exec       run a program in the workspace root (SimpleCC's language
             servers, SimpleFinder's searches, SimpleGit's git); `--tty`
             asks the transport for a terminal, which SimpleRemoteTerminalSpec
             uses so remote shells share the ControlMaster connection and
             the same PATH prelude the language servers get.
  probe      report the remote environment and latency.
  download   stream a remote file — or, with `--recursive`, a directory
             through tar — into a local path, staged beside the destination
             and activated by rename.
  upload     the reverse: a local file or directory into the workspace,
             refusing an existing destination unless `--force`.
  capabilities
             print a JSON object describing the build.  Vim asks once per
             binary and falls back to the older exec-agent behaviour when
             the runtime predates the bridge, so a plugin update that outran
             `install.sh` still connects.

The remote agent is self-installing: every connection ships the bundled
`bin/simpleremote-agent.sh` inside the launch command, compares it with the
installed copy and replaces that copy atomically only when it differs.  A
fresh host and an updated plugin therefore need no
:SimpleRemoteInstallAgent; an unwritable destination falls back to whatever
agent is already installed.  Set g:simpleremote_agent_source to ship a
different script.

For SSH targets every runtime process uses a private, deterministic OpenSSH
ControlPath with ControlPersist (SIMPLEREMOTE_CONTROL_PERSIST, default 600
seconds; SIMPLEREMOTE_CONNECT_TIMEOUT, default 10), so the agent, the probe,
transfers, language servers, searches and terminals all share one
authenticated connection.

7. SUITE INTEGRATION                             *simpleremote-suite*

SimpleRemote never requires a sibling; each integration is feature-detected
at call time.  What each sibling consumes, so a change here can be traced:

SimpleCC     runs remote language servers through `simpleremote-daemon
             exec` (workspace.runtime) and reads the remote simplecc.json
             from g:vimrc_remote_simplecc_config; it owns the LSP lifecycle
             on SimpleRemoteConnected/Disconnected, attaches to buffers on
             SimpleRemoteBufferRead, reloads on SimpleRemoteConfigChanged and
             forwards SimpleRemoteFilesChanged to the servers.
SimpleFinder searches through g:SimpleRemoteShellCommand(), previews through
             g:SimpleRemoteReadFile(), re-roots through
             g:SimpleRemoteTreeSetRoot() and follows the connection events
             (Connecting keeps its state through a workspace switch).
SimpleTree   receives root changes through simpletree#ExternalSetRoot(path,
             'simpleremote'), with a third {watch, git} argument on an sshfs
             projection ({watch: false, git: false}, because inotify never
             reports remote changes over FUSE and git status would walk the
             network) — the two- and one-argument forms are the fallback for
             older SimpleTree.  It provides the download destination through
             simpletree#ExternalDropDirectory() and the upload source through
             simpletree#ExternalSelectedPath(), answers
             User SimpleTreeRevealForeign for remote:// buffers, and its own
             root changes arrive as User SimpleTreeRootChanged.
SimpleGit    runs git in the workspace with g:SimpleRemoteExecArgv() and
             recognises remote:// buffers through b:vimrc_remote.
SimpleTerminal
             opens g:SimpleRemoteTerminalSpec() shells and remembers the
             workspace of each session across Disconnected.
SimpleLine   shows g:SimpleRemoteStatusline() and shortens remote:// names
             relative to the workspace root.
SimpleStartify
             lists g:SimpleRemoteRecentWorkspaces() and
             g:SimpleRemoteProfiles(); its session files append
             g:SimpleRemoteSessionLines() so :SLoad reconnects and re-reads
             the remote buffers of the session (SimpleRemote listens for
             User SimpleStartifySessionLoadPost and SessionLoadPost).
SimpleClipboard
             receives copied text through simpleclipboard#CopyText() and
             reads b:vimrc_remote / b:simpleremote_path for :SimpleCopyPath.
SimpleEditorConfig, SimpleTreesitter, SimpleMinimap, SimpleMarkdown
             treat remote:// buffers (buftype acwrite) like files and refresh
             on SimpleRemoteBufferRead; SimpleEditorConfig walks
             .editorconfig files with g:SimpleRemoteReadFile().
SimpleWhichKey
             names the tree's multi-key mappings through
             simplewhichkey#Describe(..., 'n', true).

RUNTIME PROBE                                      *simpleremote-runtime-probe*

After connection the Rust runtime performs a non-blocking environment probe.
Its "probe" workspace member includes the remote host, project root, Git,
Python, Node, Python LSP, and runtime latency.  The tree and global statusline
show the latest latency.

*:SimpleRemoteProbe*
        Refresh the Rust runtime environment and latency snapshot.

Programs the runtime starts — g:SimpleRemoteShellCommand(),
g:SimpleRemoteExecArgv(), g:SimpleRemoteTerminalSpec(), transfers and the
probe — get project .venv, .conda, venv and env directories on PATH, plus
$HOME/.local/bin and $HOME/bin, without sourcing interactive shell files.
The agent's own operations (g:SimpleRemoteExecute(), :SimpleRemoteExec,
:SimpleRemoteGit, :SimpleRemoteFind, :SimpleRemoteHealth and the tree's
filesystem actions) run in the agent's environment and do not get that
prelude.

TREE COPY INTEGRATION                          *simpleremote-tree-copy*

In the virtual remote tree:

  c/x   Copy/cut the current remote node, or every marked node.
  p     Paste into the selected directory.  Directories copy recursively.
  gd    Download the selected file or directory to SimpleTree's selected
        local directory.  Without a local SimpleTree root, prompt for the
        destination.
  gu    Upload a local file or directory into the selected remote directory;
        SimpleTree's selected node is offered as the default source.
  y     Copy the remote file name.
  Y     Copy the absolute remote path.
  gy    Copy the remote text file contents.

Remote paste refuses existing destinations and preflights the complete batch
before changing anything.  Copy/cut state is scoped to its SSH host or Docker
container.  Text and local-download paths use SimpleClipboard when available.

The Rust "download" action streams bytes into a same-directory temporary file
and atomically activates it.  It never loads the complete file into Vim.
Fallback keeps text in the unnamed register.  A completed download emits
SimpleRemoteFileCopied and refreshes SimpleTree.

g:simpleremote_copy_destination        string  default: empty
        Fixed local directory for gd.  Empty asks SimpleTree for its selected
        directory/root and prompts only when no local tree is available.

g:simpleremote_copy_prompt              number  default: 0
        Prompt for every gd destination, prefilled with the integrated target.

g:simpleremote_clipboard_max_bytes      number  default: 1048576
        Maximum remote text size accepted by gy.  Zero disables the limit.

TREE ROOT INTEGRATION                           *simpleremote-tree-root*

  e     Use the selected remote directory (or file parent) as the workspace.
  U     Move the workspace to its parent, up to the remote filesystem root.
  C     Prompt for any absolute remote workspace.
  .     Restore a view-only reveal to the connected workspace root.
  d     Use the active remote file's directory as the workspace root.
  L     Toggle protection for root-changing actions.
  ?     Open the complete remote-tree key reference popup.

The virtual tree accepts the SimpleTree-compatible action surface:

  <CR>/o/Right        expand a directory or edit a file
  h/Left/BS           collapse the current node or nearest expanded ancestor
  S/V/t               split, vertical split, or tab edit
  CTRL-X/CTRL-V/CTRL-T equivalent split actions
  P                   preview while retaining tree focus
  R/H/I               refresh, hidden toggle, Git-ignore toggle
  s/gs                cycle sort mode / reverse the current sort
  F                   filter already loaded tree nodes (empty clears)
  z/f                 collapse all / reveal the active remote file
  /, ]f, [f           find visible nodes and cycle matches
  a/n, A/N, r, D      new file, new directory, rename, delete
  c/x/p               remote copy, cut, paste
  Space, gm, gM       toggle/range mark, mark siblings, clear marks
  m, ', ]b, [b        bookmark, list bookmarks, cycle visible bookmarks
  y/Y/gy/gd/gu        copy name/path/content, download to the local tree,
                      upload from it

All keys in SimpleTree's built-in help panel have a virtual-tree counterpart
except gx: a remote path has no dependable local system-default application.
Modification-time and size sorting require the current bundled remote agent;
run :SimpleRemoteInstallAgent after upgrading an older installation.

*:SimpleRemoteTreeRoot* {path}
        Change the connected workspace root.  Projection discovery, tab-local
        current directory, remote simplecc.json, and SimpleCC restart through
        the normal reconnect lifecycle.  Mounted SimpleTree roots synchronize
        in the other direction through SimpleTreeRootChanged; provider-tagged
        simpletree#ExternalSetRoot() calls do not feed back into another
        reconnect.  Set g:simpleremote_sync_tree_root to 0 for the historical
        view-only behavior.
